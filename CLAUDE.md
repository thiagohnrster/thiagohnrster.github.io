# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Ver também [CONTEXT.md](CONTEXT.md) para o contexto de negócio/conteúdo do site (seções, projetos exibidos, débito técnico).

## Visão geral

Portfólio pessoal estático de Thiago Celestino (dev front-end), em português. Página única (`index.html`), sem framework, sem back-end, sem etapa de build — HTML/CSS/JS são servidos como estão. Hospedado no GitHub Pages.

## Comandos

Não há scripts de build, lint ou teste configurados em `package.json` (`npm test` só retorna erro proposital). O único comando relevante:

```bash
npx live-server
```

Sobe um servidor local com auto-reload ao salvar qualquer arquivo. `live-server` é a única dependência do projeto.

Deploy é automático: qualquer push em `main` dispara `.github/workflows/jekyll-gh-pages.yml`, que publica os arquivos estáticos no GitHub Pages via `actions/jekyll-build-pages`. Não existe `_config.yml` nem nada específico do Jekyll — o workflow apenas repassa os arquivos como estão.

## Arquitetura

**Tudo gira em torno de `index.html`.** As seções (`#intro`, `#stats`, `#sobre`, `#projetos`, `#contato`) estão todas nesse único arquivo, dentro de `<div class="master">`. Não há roteamento nem outras páginas HTML no domínio principal.

**Separação de responsabilidades em `js/`:**
- `js/loader.js` — tela de carregamento inicial (ver seção própria abaixo). Carregado com `defer`, antes de `site.js`.
- `js/site.js` — tudo que é decorativo/scroll: registra `ScrollTrigger` no GSAP, detecta a seção ativa no viewport para marcar o link do menu, timeline de entrada do hero, parallax da ilustração, reveal de título letra-a-letra via `SplitType`, efeito de "digitação" nos pre-titles (`preparePreTitleTyping()`), fundo animado de átomos de UI no hero (`heroAtomsBackground()`), console de skills animado em "Sobre" (`skillsConsoleAnimate()`), cursor customizado em todo o site (`cursorCaret()`), animação de contadores da seção de stats. Respeita `prefers-reduced-motion`.
- `js/scripts.js` — tudo que é interação de clique: abre os modais de projeto (`$.dialog` do jquery-confirm), aplica `.scrolled` no header ao rolar, implementa scroll suave para links `.scroll-to` (mesmo cálculo de offset usado pelos links do menu em `site.js` — ver nota abaixo), limpa o hash da URL após navegar, controla o painel do menu mobile (`mobileNavToggle()`).
- Demais arquivos em `js/` são bibliotecas de terceiros (GSAP, ScrollTrigger, SplitType, jQuery + Migrate, jquery-confirm, jquery.visualnav, lucide, Lenis) — **não editar como se fossem código próprio**.

**Tela de carregamento (`#pageLoader`)** é o primeiro elemento do `<body>` em `index.html`, controlada por `js/loader.js`. O progresso da barra reflete carregamento **real** — soma ponderada de `document.fonts.ready`, o load da ilustração do hero e o evento `window.load` — suavizado por interpolação, não um timer falso; não trocar por um timer fixo. Ao terminar, `loader.js` resolve a promise `window.__pageLoader.ready`. `site.js` usa o helper `whenPageReady()` pra só armar a entrada do hero (o `IntersectionObserver` de `heroIntro` e o `ScrollTrigger` de `heroLeft`) depois que essa promise resolve — sem esse gate a animação tocaria escondida atrás do loader, já que o hero está visível desde o primeiro paint. Qualquer nova animação de entrada do hero deve passar pelo mesmo gate.

**Scroll suave para âncoras é calculado, não delegado a uma lib.** `window.smoothScrollTo(target)`, definida no topo de `js/site.js`, calcula o destino (altura do header **em repouso** via `headerHAtRest()` — simula a classe `.scrolled` mesmo antes de a página ter rolado, já que o header fica mais baixo assim que o scroll começa — menos um `SCROLL_GAP` fixo de 40px, ancorando em `.content .pre-title` da seção-alvo quando ela existir, pra evitar parar no respiro de 180px de padding-top da seção) e dispara `window.scrollTo({ behavior: 'smooth' })`. É usada tanto pelos links `a.nav-link` do menu quanto pelos elementos `.scroll-to` (logo e botão "Saiba mais" em `js/scripts.js`) — a função fica em `site.js` porque esse script carrega (`defer`) antes do corpo de `scripts.js` rodar (dentro do `$(document).ready`). Não duplicar esse cálculo de volta em `scripts.js`.

**Efeito de "digitação" nos pre-titles** (`preparePreTitleTyping()` em `site.js`) transforma o texto após o "//" num bloco cuja largura é revelada em steps (simulando caractere a caractere), com um caret que some só ao final. O timeline retornado não roda isolado — é encaixado (`.add(tl, 0)`) na mesma timeline que já faz o fade de entrada da seção (hero, sobre, projetos, contato), pra tocarem sincronizados por construção. Respeita `prefers-reduced-motion` (define a largura final direto, sem animar).

**Modais de projeto são fragmentos HTML separados, carregados via AJAX.** Cada card em `#projetos` (`card_1`…`card_4`) tem um handler em `scripts.js` que abre um `$.dialog()` apontando para `modals/*.html` (`hdc-eventos.html`, `rubrum.html`, `rubrum-site-v1.html`, `rubrum-site-v2.html`). Cada arquivo em `modals/` é um `<div>` isolado, sem `<html>`/`<head>` próprios — ao editar um modal, mantenha esse formato de fragmento. O mapeamento card → modal está documentado em [CONTEXT.md](CONTEXT.md).

**Fundo animado de átomos no hero (`.hero-atoms`, `heroAtomsBackground()` em `site.js`).** Um `<canvas>` 2D dentro de `.hero .container` desenha ~30 ícones de componentes de UI (botão, toggle, checkbox, cursor, etc. — não código, não rede de pontos, ver histórico de decisões) à deriva atrás do conteúdo. Cada átomo tem uma `depth` contínua (0.2 longe .. 1.0 perto) da qual derivam tamanho, opacidade, espessura do traço e velocidade — é isso que vende a sensação de profundidade, não dois grupos fixos. Reage a paralaxe de mouse e de scroll (`ScrollTrigger` com `scrub`, mesma técnica de `heroLeft()`). **Cuidado ao mexer no wrap-around:** o cálculo de quando um átomo "sai por um lado e reaparece do outro" precisa usar a posição **renderizada** (lógica + paralaxe), não só a lógica — um bug já aconteceu aqui porque o paralaxe de scroll (até ±75px) empurrava átomos de volta pra dentro da área visível depois de já terem sido considerados "fora", cortando a forma na borda do canvas. Uma vinheta elíptica (`.hero-atoms-vignette`, `radial-gradient(ellipse at center, transparent 45%, #001833 88%)`) sobrepõe o canvas pra também mascarar qualquer corte residual nas bordas — elipse, não círculo, porque o hero é bem mais largo que alto. Outro gotcha já corrigido: `resize()` recentraliza `mouse.x`/`mouse.y` no meio do hero — sem isso o valor inicial `{x:0, y:0}` (canto superior-esquerdo) enviesava o paralaxe pra esquerda até o primeiro `mousemove` de verdade dentro do hero. Pausa via `IntersectionObserver` (fora da viewport), `visibilitychange` (aba em background) e não roda em `prefers-reduced-motion` (desenha 1 quadro estático).

**Frame unificado dos cards de projeto (`.card-chrome` + `.card-art` + `.card-duotone` em `#projetos`).** As 4 imagens reais dos projetos (`images/layout/project_thumb_*.png`) têm origens visuais muito diferentes entre si (screenshot de painel, render de marketing rosa, foto de evento) — sem tratamento comum isso lia como inconsistência. Cada `.card-picture` ganhou uma barra de chrome falsa (3 bolinhas + um retângulo curto sem texto simulando uma barra de endereço) e a imagem passou a ficar dentro de `.card-art`, com `filter: grayscale(.85)` na `<img>` e um `.card-duotone` (`mix-blend-mode: multiply`) por cima — a imagem é dessaturada *antes* do duotone entrar, senão cores muito saturadas na origem (o vermelho da Rubrum) furam a tinta azul e continuam destoando. Os cards também ganharam `.card-description` (uma linha de contexto sob o título, ex: "Landing page · Redesign") e foram reordenados no HTML pra mostrar os projetos com data real primeiro, "Prévia em breve" depois — prova social antes de expectativa.

**Console de skills em "Sobre" (`.term`, `skillsConsoleAnimate()` em `site.js`) substitui barras de porcentagem.** Em vez de uma métrica auto-atribuída ("95% em HTML", sem lastro nenhum), a seção mostra a saída de um `node skills.js` fake: HTML5/CSS·Sass/Javascript/Angular JS aparecem como barras ASCII (`■■■■`) indicando em quantos dos 4 projetos reais da seção Projetos aquela tecnologia foi usada (contagem real, verificável clicando em Projetos) — UI/UX e Design Responsivo, que não são uma tag de projeto, ganham uma frase qualitativa em vez de um número inventado. A animação reaproveita a mesma técnica de `preparePreTitleTyping()` (revelar largura via `ease: steps(n)`) generalizada num `typeReveal()` local, tanto pro comando digitado quanto pras barras ASCII, disparada por `ScrollTrigger` (`onToggle` reversível, mesmo padrão de `heroLeft()`).

**Cursor customizado em todo o site (`.cursor-caret`, `cursorCaret()` em `site.js`).** Um bloco azul piscando estilo cursor de terminal segue o mouse (`translate3d` num `requestAnimationFrame`), substituindo o ponteiro do sistema — `.has-custom-cursor` aplica `cursor: none` globalmente, só ativado depois do primeiro `mousemove` real (pra nunca existir um instante sem nenhum cursor visível). Sobre links/botões/cards o bloco vira um círculo em vez de sumir, preservando o sinal de "isso é clicável" sem depender da mãozinha nativa. Só ativa com `pointer: fine` (sem efeito em touch). **jQuery Confirm exige um override específico:** a lib usa `z-index: 99999999` no overlay do modal (nosso `.cursor-caret` precisa ficar acima disso, hoje em `100000000`) e define `cursor: pointer` no botão de fechar com especificidade maior que `.has-custom-cursor *` — por isso existe `.has-custom-cursor .jconfirm-box * { cursor: none !important; }` — e `.jconfirm-closeIcon` está na lista `INTERACTIVE` do script pra ganhar o círculo de hover.

**Responsividade real abaixo de ~900px (`@media (max-width: 900px)` em `style.css`).** O layout era efetivamente fixo pra desktop: `.container` tinha `min-width: 960px` e `header` tinha `min-width: 1009px`, e como `.master` usa `overflow-x: clip`, telas mais estreitas simplesmente cortavam conteúdo em vez de rolar — apesar da seção "Sobre" anunciar "Design Responsivo" como skill comprovada. Os dois `min-width` foram removidos e o breakpoint reflowa de verdade: header vira logo + botão de menu, hero empilha (ilustração acima do texto), stats vira grade 2×2, "Sobre" empilha texto + console de skills, cards de ferramentas passam a 2 colunas, cards de projeto viram coluna única, e o modal de case (`.jconfirm-box`, `.jc-dialog-flexbox-container`) também reflowa (vídeo acima do texto). Há um segundo breakpoint, `@media (max-width: 375px)`, só pra ajustes finos de telas bem estreitas. Ajustes finos posteriores no breakpoint de 900px: `.stats-label` e `.card-title` ganharam regras próprias de tipografia mobile (`Source Code Pro`, tamanho reduzido) — antes herdavam o tamanho desktop, grande demais para os cards/stats empilhados em telas estreitas.

**Menu mobile (`.nav-toggle` + painel em `.navigation`, `mobileNavToggle()` em `scripts.js`).** Abaixo de 900px, o botão hambúrguer (3 `<span class="nav-toggle-bar">` que giram e viram um X via CSS, sem SVG novo) alterna a classe `nav-is-open` no `header`. Nesse estado, `.navigation` — que no desktop é só a barra horizontal com os 3 links + CTA — passa a `position: fixed`, cobre a tela abaixo do header e fica com fundo sólido + blur (reaproveita a cor de `header.scrolled`). Gotchas já corrigidos aqui, não reintroduzir:
- **Scroll lock preservando posição.** `overflow: hidden` sozinho no `html`/`body` faz o navegador (principalmente mobile) descartar o scroll atual e voltar pro topo quando o painel abre no meio da página. `openMenu()` guarda `window.pageYOffset` e fixa o `body` nessa posição via `top` negativo (`html.nav-open body { position: fixed }` no CSS); `closeMenu()` restaura com `window.scrollTo`.
- **Ordem de handlers no clique de um link do menu.** O scroll suave de verdade é disparado pelo handler de `site.js`, ligado direto no `<a>` (fase de bubble). Fechar o painel só na fase de bubble deixaria a ordem entre os dois handlers dependente de qual script bindou primeiro — e como fechar o menu tira o `html.nav-open` (que trava o scroll), se isso rodasse depois do handler de `site.js`, o `window.scrollTo` já teria sido chamado com a página ainda travada e não rolava nada. Por isso `mobileNavToggle()` escuta o clique na fase de **captura**, a partir do `<nav>` (ancestral do link) — fecha e libera o scroll antes do clique chegar no `<a>`. Esse listener só chama `closeMenu()` se `nav-is-open` estiver de fato presente — sem esse `if`, ele disparava em qualquer clique num link do menu, inclusive no desktop, onde `lockedScrollY` nunca é atualizado (fica `0`) e o `window.scrollTo(0, 0)` jogava a página pro topo antes do cálculo de destino de `site.js`.
- **`backdrop-filter` em ancestral quebra o `backdrop-filter` do painel — mas só quando some o `background` junto.** Um `header.nav-is-open { background: none; backdrop-filter: none; }` já foi reintroduzido por engano mais de uma vez dentro do breakpoint: o `background: none` apagava o fundo do próprio header (que deveria herdar o mesmo estilo de `header.scrolled`). Essa combinação (background + backdrop-filter juntos) não deve voltar. Ajuste fino intencional, mantido: `header.nav-is-open` sozinho ganhou `backdrop-filter: none` (sem mexer no `background`) pra evitar duplo-blur — sem isso, o blur do próprio header somado ao `blur(20px)` do `.navigation` (seu descendente, que amostra o que está atrás do header) deixava o painel mobile com um desfoque mais pesado que o pretendido. `header.nav-is-open .logo` também passou a usar o mesmo tamanho reduzido de `header.scrolled .logo` (42px), e o fundo do painel foi clareado de `rgba(0,0,0,.8)` para `rgba(0,0,0,.65)`.
- **`onScroll()` (em `site.js`, ver `navActiveBySectionRange`) ignora recálculo enquanto `html.nav-open` está presente.** Durante o scroll lock, `window.pageYOffset` lê `0` de verdade (a posição visual é só simulada via `body{top}`) — sem essa guarda, qualquer recálculo nesse meio tempo marcava sempre "Home" como link ativo, e essa marcação ficava presa lá até o próximo scroll real.
- Fecha ao clicar num link do menu, no Esc, ou se a tela voltar a ficar larga (`matchMedia('(min-width: 901px)')`) com o painel ainda aberto.

**O reveal de título por caractere (`contentIsIn_andTitleAnim()` em `site.js`) observa o `.main-title`, não o `.content` inteiro.** No breakpoint mobile, `.content` passou a englobar conteúdo empilhado bem mais alto que a viewport (console de skills em "Sobre", cards em coluna única em "Projetos", lista em "Contato") — um `IntersectionObserver` com `threshold: 0.55` sobre o `.content` inteiro nunca batia esse valor, e a animação nunca disparava. O observer mede a visibilidade do título em si (altura estável, curta) e resolve o `.content` ancestral via `closest('.content')` só para aplicar a classe `is-in` e montar a timeline — não reverter pra observar o `.content` direto.

**CSS é um único arquivo escrito à mão:** `styles/css/style.css`. Não há Sass/Less ativo — `styles/scss/` existe mas está vazia e sem uso. Não introduzir um pipeline de build a menos que explicitamente pedido.

**Fontes self-hosted:** Plus Jakarta Sans (6 pesos) e Source Code Pro (5 pesos, usada nos "//" dos pre-titles e no loader) em `styles/fonts/`, referenciadas via `@font-face` em `style.css` — múltiplos formatos por peso, para compatibilidade ampla de navegador (não remover formatos sem necessidade). Todas as faces têm `font-display: swap`; as 3 usadas no primeiro paint (`plus_jakarta_sansextrabold`, `plus_jakarta_sanssemibold`, `SourceCodePro-Medium`) têm `<link rel="preload">` em `index.html`, antes dos stylesheets.

**Ícones:** só o set **Boxicons** (`bx`/`bxf`/`bxl`, carregado em `index.html`) está de fato em uso. Font Awesome, Tabler Icons e `lucide.js` foram removidos do repo por não terem uso — não reintroduzir sem necessidade real.

## Notas específicas

- Todos os `<script>` de terceiros no `<head>` (GSAP, ScrollTrigger, SplitType, jQuery, jQuery Migrate, jquery-confirm) têm `defer`, assim como `loader.js`, `site.js` e `scripts.js` — antes só os dois últimos tinham, e os demais bloqueavam o primeiro paint. A ordem no HTML continua sendo a ordem de execução (scripts com `defer` rodam em sequência, depois do parsing), então não precisa de `$(document).ready` extra pra garantir que `jQuery`/`GSAP` já existem quando `site.js`/`scripts.js` rodam.
- `<html lang="pt-BR">` (não `en`) — todo o conteúdo é em português.
- `index.html` tem Open Graph/Twitter Card (`og:title`, `og:image` apontando pro thumbnail da Rubrum, etc.) e `<link rel="canonical">` pra `https://thiagohnrster.github.io/` — sem isso, o preview do link no WhatsApp/LinkedIn saía sem imagem/descrição.
- Todo link `target="_blank"` (ícones sociais do hero, lista de Contato, botão "Chamar no Whatsapp") tem `rel="noopener noreferrer"`.
- Não adicionar um link "Contato" na navegação do header — o botão CTA "Entre em contato" (`mailto:`) já cobre esse propósito.
- `js/jquery.visualnav.min.js`, `js/lenis.min.js`, `js/lucide.js`, `styles/css/fontawesome/` e `styles/css/tabler-icons/` foram removidos do repo por serem resíduo sem uso (o destaque do link ativo do menu é feito por lógica própria em `site.js`; o smooth scroll é feito via `window.scrollTo({ behavior: 'smooth' })` nativo — ver cálculo de offset acima).
- `plus_jakarta_sanslight` e `plus_jakarta_sansmedium` (`@font-face` + arquivos em `styles/fonts/`) não são referenciados em nenhuma regra de `style.css` — confirmado que o navegador nunca os baixa. Débito técnico, mantidos por enquanto a pedido do usuário.
- Botões de ação (`.btn`, `.jc-dialog-links .link`) usam `border-radius: 15px` — badges/tags de status e tecnologia (`.card-description-status`, `.ui-badge`, `.ui-pills .pill`) continuam pill (`border-radius: 64px`/`999px`). É uma distinção deliberada (rótulo vs. ação), não inconsistência — não uniformizar os dois grupos sem necessidade.
- `window.addEventListener('unload', ...)` foi trocado por `'pagehide'` nos três handlers de limpeza em `site.js` (`heroIntro`, `heroAtomsBackground`, `contentIsIn_andTitleAnim`) — `unload` é bloqueado por Permissions Policy em navegadores modernos (quebra o bfcache). Não reintroduzir `unload`.
- O cursor customizado (`cursorCaret()`) esconde o ponteiro nativo do sistema inteiro — texto selecionável (parágrafos do "Sobre", contato) perde o indicador visual de I-beam, mas a seleção em si continua funcionando normalmente. Trade-off aceito, não é um bug.
